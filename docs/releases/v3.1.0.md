# Harmony v3.1.0 Release Notes

**Status:** stable release

**Released:** 2026-10-04

**Upgrade path:** v3.0.0 → v3.1.0

Harmony v3.1.0 builds on the focused v3 workflow:

**Sources → Downloads → Library → M3U/Navidrome**

It adds ways to bring your own files into the Library, fix their tags, and
protect the installation, and it redesigns the web interface. There are no
removals or breaking API changes. One database migration
(`20260825_0033_operations_automation`) runs automatically at startup.

Do not delete or recreate `harmony.db` when upgrading. Back up the database,
`.env`, playlist files, and artwork cache before switching an existing
installation to v3.1.0.

## Local music uploads

- Upload many files at once from the Library page. Files are staged privately
  and reviewed before anything reaches the Library.
- Review works per album: shared metadata, track-number gaps and duplicates,
  and inconsistent album fields are flagged before import.
- MusicBrainz-assisted album matching, plus manual or Cover Art Archive
  artwork, embedded across the album at import.
- Download-site branding in filenames, tags, comments, and lyrics is proposed
  for removal, with every change visible before import.
- A duplicate preflight compares staged files with the Library by path,
  provider IDs, ISRC, metadata, and duration. Exact and strong matches are
  skipped by default; indexed files are never replaced.
- Imports run as resumable `library_import` tasks with progress, cancellation,
  and restart recovery, and request one Navidrome scan per batch.
- Storage guardrails cap batch size, reserve free space, and expire unfinished
  batches. They are configured with the `LIBRARY_UPLOAD_*` variables in
  `.env.example`.

## Library metadata editor

- Edit title, artist, album, album artist, genre, year, track, and disc for a
  song. Saving writes the audio file and refreshes the Library index at once.
- Search MusicBrainz with independently editable terms; results are previews
  until you choose one and save.
- Replace artwork with a JPEG, PNG, or WebP file, or import it from the Cover
  Art Archive.

## Operations

- **Settings → Operations** downloads a consistent backup of the database and
  cached artwork, and can restore one.
- Settings export and import as portable JSON. Environment secrets and paths
  are excluded.
- Each Source records automatic and manual schedule runs, shows late runs, and
  keeps a run history.
- Restart Harmony after a restore or settings import.

## Navidrome 0.64

Harmony detects Navidrome's ID scheme and, once after an ID migration (or on
demand from the Dashboard's **Refresh IDs** action), remaps stored song and
playlist IDs. Reconciliation only reads from Navidrome and skips while it is
scanning. Back up Navidrome's data before upgrading it to 0.64.

## Interface

- A redesigned UI built on a shared design system, with a reorganized
  Dashboard and simpler page headers and cards.
- Five mobile tabs (Dashboard, Downloads, Sources, Playlists, Library), with
  Settings in a phone-only top bar.
- Every failed download now offers **Download from a YouTube link**, not only
  matching-related failures.

## Container publication

| Event | Published tag |
| --- | --- |
| Push to `main` | `latest` and `sha-*` |
| Push of the `v3.1.0` Git tag | `v3.1.0`, `latest`, and `sha-*` |
| Pre-release tag such as `v3.2.0-rc.1` | that tag only |

Published images use `linux/amd64`.

```bash
docker pull ghcr.io/azimul-kabir/harmony:v3.1.0
```

## Upgrade checklist

1. Back up the persistent database and configuration, and Navidrome's data if
   you also upgrade it to 0.64.
2. Pull the v3.1.0 image and keep the existing volume mappings.
3. Confirm `/health/ready`, login, Sources, Downloads, Library, and Playlists.
4. Download a backup from **Settings → Operations** and keep it.
5. Upload a small album through the Library page and confirm the import.
6. Keep the v3.0.0 image reference available for rollback. Switching the image
   tag does not roll back the database migration.
