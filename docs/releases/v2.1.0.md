# Harmony v2.1.0 Release Notes

**Release date:** 2026-08-08  
**Upgrade path:** v2.0.1 → v2.1.0

Harmony v2.1.0 secures the application boundary, expands playlist acquisition
and Navidrome automation, and hardens download and synchronization correctness.

## Highlights

- **Authenticated web access:** The UI, JSON API, SSE feeds, and interactive
  API documentation now require a signed login session by default. Static
  login assets and health probes remain public.
- **YouTube Music playlist Sources:** Save public YouTube Music playlists,
  preserve their order and provider identity, queue missing entries, export
  M3Us, and reconcile them with Navidrome using the existing Source workflow.
- **Deeper Navidrome integration:** Love or unlove every song in a Navidrome
  playlist, generate playback-statistics auto-playlists, inspect sync health,
  and trigger bounded scans with safer path matching and reconciliation.
- **Safer acquisition:** Spotify fallback results remain available when the
  URL attempt yields no audio, but every candidate must pass strict artist,
  title, recording-version, and reliable-duration validation before import.
- **Better YouTube metadata:** Canonical playlist metadata and artwork survive
  acquisition and can be repaired through the Library artwork workflow.
- **Operational reliability:** Download duration telemetry, SpotDL attempt
  timing, atomic task progress, and reduced SQLite worker contention improve
  diagnosis and large-playlist behavior.

## Breaking deployment requirement

Docker Compose now requires a non-empty `WEB_AUTH_PASSWORD`. Before upgrading,
copy the current `.env.example` additions into `.env` and set a long, unique
password:

```env
WEB_AUTH_ENABLED=true
WEB_AUTH_USERNAME=admin
WEB_AUTH_PASSWORD=replace-with-a-long-unique-password
WEB_AUTH_SESSION_HOURS=12
WEB_AUTH_SECURE_COOKIE=false
```

Authentication fails closed when enabled without a username or password. Set
`WEB_AUTH_SECURE_COOKIE=true` when the browser reaches Harmony over HTTPS. The
portal does not provide TLS or brute-force protection, so internet-facing
deployments should remain behind a suitably secured HTTPS reverse proxy.

## Database migrations

Startup applies Alembic revisions `20260725_0026` through `20260730_0030`:

- local lyrics support;
- provider-aware Song source identities;
- Navidrome playback statistics used by automatic playlists;
- persisted download-job duration; and
- provider-aware playlist Source identity.

The Source migration preserves existing Spotify rows and converts their legacy
fields into the canonical provider/external-ID representation.

## Upgrade

1. Back up Harmony's database, `.env`, and playlist files.
2. Update `.env` with the web-authentication settings above.
3. Pull or build the v2.1.0 image and start Harmony normally.
4. Open `http://localhost:8080/login` and sign in.
5. Verify the public health endpoints:

   ```bash
   curl --fail http://localhost:8080/health/live
   curl --fail http://localhost:8080/health/ready
   ```

6. If Navidrome is configured, use **Settings → Navidrome → Test Connection**
   and review synchronization health before running a full scan.

## Compatibility notes

- Public YouTube Music playlist Sources require yt-dlp and the YouTube Music
  provider to be enabled. Private playlists and cookie-based access are not
  supported.
- Love/Unlove and playback-statistics auto-playlists operate as the configured
  Navidrome user and require valid Subsonic credentials.
- The original `/health`, `/health/live`, and `/health/ready` deployment probes
  remain accessible without a login.
