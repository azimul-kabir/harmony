# Harmony v2.0.1 Release Notes

**Release date:** 2026-07-26
**Upgrade path:** v2.0.0 → v2.0.1

Harmony v2.0.1 is a stabilization release. It does not introduce a database
migration or change managed music files.

## Highlights

- Added GitHub Actions gates for Python 3.12 compilation, the full pytest
  suite, and a production Docker image build.
- Consolidated SQLAlchemy engine and session creation into one canonical
  module, removing two session factories with different behavior.
- Preserved the lightweight `/health` compatibility endpoint and added:
  - `/health/live` for process liveness.
  - `/health/ready` for database, migration-marker, and required-storage
    readiness.
- Reconciled the roadmap with duplicate resolution, manual artwork, local
  lyrics indexing, and PWA support that are already shipped.
- Corrected the PWA cache-version regression test.

## Upgrade

1. Back up Harmony's database and configuration.
2. Replace or rebuild the Harmony container with v2.0.1.
3. Start Harmony normally. No new Alembic migration is required.
4. Verify liveness:

   ```bash
   curl http://localhost:8080/health/live
   ```

5. Verify readiness:

   ```bash
   curl --fail http://localhost:8080/health/ready
   ```

Readiness returns HTTP 503 until the SQLite database is accessible and the
music, download, staging, failed-download, and artwork-cache directories are
present and writable.

The original `/health` endpoint remains available for existing Docker,
Synology, and reverse-proxy configurations.
